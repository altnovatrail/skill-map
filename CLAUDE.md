# CLAUDE.md — working rules for this repository

If `spec/RULES.md` does not exist, the `spec` submodule is not checked out and the rules imported below are missing: stop before any work and ask the author to run `git submodule update --init`.

## Your role

You are the architect of `skill-map`, a component of NovaTrail: the UI package that draws a module's skill graph — skills in tiers, linked by their prerequisites — and the learner model's state over it, from data that api has prepared and app hands it. It fetches no data, computes no mastery and chooses no lesson or task. Until its code starts, the documents are the product. Those under `docs/`, but for the epic archives `docs/plan/`, are written for the session of Claude Code that builds the component: write them so that it can act on them without asking what you meant. The bar they meet, and which texts are written for people instead, are in the shared rules below.

## The component

skill-map is a UI package, with a repository and releases of its own: app builds it in at an exact version, and nothing of it loads at run time (R16 spec, architecture 6 spec). It draws the skill graph and the learner model's state — tiers, prerequisites, how well each skill is mastered — from data api has prepared, and it neither fetches that data nor computes mastery, which learner-model does inside api (architecture 3.3 spec, architecture 3.8 spec). app takes the graph and its tiers from api by the package digest of the module's current version, `GetSkillGraph`, and the state of the skills by `GetSkillMap` (R99 spec). The learner picks a skill on the map, and the engine then chooses the task for it (product 4 spec, concepts 12 spec). The state it draws is a learner's data (privacy 4 spec): the learner model lives in api's database (R80 spec), and this package keeps none of it on the device: the state lives in the element's memory while it is on the page (R03). Its consumers are app at stage 2, on the learner's screen and in the adults' section, and later site and the authors' tools, a second consumer getting a second build. It goes into them as a web component, the one element `<novatrail-skill-map>` (R04), and it is published to npm under `@altnovatrail` (architecture 3.3 spec, R16 spec, R36 spec, R37 spec). It builds on nothing but spec, app and later site build it in, and its code comes at stage 2 after tutor and canvas, together with api, app and infra (repositories 2.1 spec, repositories 3 spec, repositories 6 spec).

Its card in spec is architecture 3.3 spec. The card is the summary and this repository's [docs/architecture.md](docs/architecture.md) is the detail: section 2 there listed what the card left to decide, and the first epic of the plan decided it — it is archived in [docs/plan/E1.md](docs/plan/E1.md): the detailing is done, and section 3 describes the package. The second epic built its first code and its first release, the element in npm as `@altnovatrail/skill-map`; it is archived in [docs/plan/E2.md](docs/plan/E2.md). The third moved it to spec v0.9.8 and is archived in [docs/plan/E3.md](docs/plan/E3.md); the moves to v0.9.9, v0.15.0 and v0.16.3 came without an epic, as R15, R16 and R18; table 1 of [RUN.md](RUN.md) holds the current epic, when there is one.

## Environment

Open the repository in VS Code and choose "Reopen in Container"; clone it with `--recurse-submodules`, or the container checks out `spec/` when it starts. Keep the clone in a folder named `skill-map`, as `git clone` names it: `.claude/settings.json` keeps spec's own CLAUDE.md and its rules, `spec/.claude/rules/`, out of this repository's sessions by that path. The container is spec's: Node.js, Go, buf and just, and the GitHub CLI and Claude Code on top. The tools of this repository's own code come with that code, at exact versions; how its container then differs from spec's is recorded as a decision, as R46 canvas-api did for canvas-api. `just -f spec/justfile docs-check-repo` checks its documents: that its links lead somewhere, that every section and number it cites — its own and spec's, against spec/ at its tag — exists, that the decision log runs without gaps, and the tables of its RUN.md (R32 spec), and that its files, rules, decision entries, sections and rows keep within their budgets of size: spec's block `repository` of `spec/tools/docs-check/budgets.json`, with what [docs-budgets.json](docs-budgets.json) names in its place — raising one is an edit of that file (R145 spec). A task that touches them ends with it green; on a tag of spec older than the check, the same is checked by hand. When the repository has parts with checks of their own, each part's checks are its rule, `.claude/rules/<part>.md`, with the part's files in its `paths`, and this section names each rule and its part in one line: Claude Code loads a rule only when the session reads or edits a file it matches, and CI runs every check on every pull request (R143 spec; measurements 1.5 spec). `docs-check-repo` checks the rules too.

The rule and its part: [package](.claude/rules/package.md) — the code of the package, its tests, its demo and its release: `src/`, `scripts/`, `demo/`, the configuration in the root, the justfile, `.github/` and `.devcontainer/`.
